# 学术任务层

处理论文写作、MATLAB 仿真与出图、论文评阅时适用。**不适用时不要提及本文件，也不要往固件任务里套用。**

## 进入判据

判据看**产出物**，不看话题。两边都沾时只问一次「这次按论文还是按固件」，问完记在当前会话里，不重复问。

| 本次产出物 | 归哪层 | 加载 |
| --- | --- | --- |
| `.tex` 正文、`.bib`、摘要、图题、公式、文献回顾、篇幅 | 写作 | `academic-voice` |
| `.m`、仿真运行、结果文件、出图、复现 | 仿真 | `academic-sim-run` |
| 问题清单（评别人的论文或自己的稿） | 评审 | `academic-audit` |
| 只涉及 STM32、驱动、中断、DMA、Bootloader | 固件 | 见 `embedded.md` |

命中以下情形**直接加载，不经过判断**：

- 改 `.tex`、`.bib`、正文、摘要、图题、公式 → `academic-voice`
- 跑或改 `.m`、出图、复现、换机器 → `academic-sim-run`
- 给 PDF 或稿件出问题清单 → `academic-audit`

## 硬门禁：先方案，后动手

学术任务里，改文件（`.tex`、`.bib`、`.m`、`.fig`）之前**必须先给方案**，等明确同意再改。这不是建议：

- 方案要写清：改哪个文件、哪一段、改成什么、为什么改、改成什么样。
- 方案里要**列出前后对比**，只说「已优化」不算交付。
- 自己判断用户意见不成立时，直接说明冲突和依据，不默认照做。
- 用户说「直接改」「改吧」才进入编辑；「你看看」「给个方案」都只出方案。

证据：`A14`（先给整体思路，别急着改或跑）、`A22`、`B9`、`B10`、`B66`。

## 方向锚点

论文类任务开工前先读方向锚点，1 页，防跑偏。按顺序找，**找到就用，找不到就问，不自动新建**：

1. 当前工作区 `学术记录\DIRECTION_ANCHOR.md`
2. 上一级目录 `学术记录\DIRECTION_ANCHOR.md`（在子目录开会话时兜底）
3. 都没有 → 问一句「这次按哪篇论文？要不要建锚点」，**不得自行推断研究方向**

路径一律相对工作区，不写盘符。锚点包含：研究问题、贡献列表、目标页数、图↔正文对应表、禁写清单。

## 按目的取规则（不整本读）

每条规则只存一份；跨技能要用时写「见 X.Y」，不复制。

| 这次要做 | 读 |

## 输出约定

- 汇报用中文；**方案里不贴 LaTeX 源码**，用文字描述改法，除非明确要看代码。
- 改动一律给前后对比。
- 不虚构文献、DOI、期刊名、仿真数据、性能数字；查不到就写「未核实」。

证据：`B19`（方案不要写 LaTeX 格式）、`B122`、`B195`。

## 保险模式下的锚点

流程复用保险模式的通用步骤（`embedded.md` 里有完整定义；该文件未常驻时按这 6 步走）：

1. 范围声明：允许改的段落与文件、禁止改的部分、验收标准、待确认项。等确认。
2. spec：只写设计与措辞，不改文件。等确认。
3. 任务卡：5~10 条，每条带完成判据。等确认。
4. 执行：一次一张卡，做完报三行。
5. 收口：`academic-reviewer` 只给 diff、锚点、验收标准；改过就重审一次，最多两轮。
6. 交证据（按通用三档），用户抽检最高风险项。

**只换锚点**：

| 交给只读审稿者时 | 锚点内容 |
| --- | --- |
| 论文改动 | 研究问题、贡献列表、目标页数、图↔正文对应表、禁写清单 |
| 仿真改动 | 参数表、图-代码-结果三元组、复现命令、与旧结果的差异 |

固件任务的锚点仍见 `embedded.md`，此处不重复。
