# 写作规则（academic-voice）

规则来源：SR 论文四个会话的 453 条用户原话。每条末尾 `[证据 Xnn]` 指向 `evidence.md`。
**这些是用户的个人习惯，不是通用英语规范。与稿子现状冲突时先指出冲突，不擅自统一。**

---

## 10.1 用词、句式、标点

### 禁用词（见到就换，不要解释理由）

| 不用 | 换成 | 证据 |
| --- | --- | --- |
| `on top of` | 直接删掉，或 `in addition to` 之外的重写 | B45 |
| `heterogeneity` | `different types of IoT services`、`within shared physical infrastructure` | B45 B46 |
| `recast` | `transform`、`convert`、`rewrite as` | B134 |
| `behavior` | `performance`、`trend`，或直接说现象 | B171 |
| `Here, ...` 起句 | 用 `where` 接上一句 | B258 |
| `completion latency` | `weighted-sum latency`、`system latency` | A62 A63 |
| `Specifically` 起段落首句 | 会让两段读起来像没分段，删掉 | B84 |
| `harvest-then-transmit` | 换成本文自己的表述 | B74 |
| `computation-rate maximization` | `maximization of computation rate`（名词化连写要拆开） | B78 |
| `communication--computation resources` | 拆成两个并列名词，不用连字符堆叠 | B54 |
| `Let the starred variables denote ...` | 「通过标准凸优化求解，回代得到原变量」这类直白说法 | A137 |
| `The Hessian of the transformed ... function` | 直接写函数名，不绕 | A130 |
| `The left-hand side of C3 is ...` | 直接说这个约束表达什么 | A131 |

### 句式

- **不用「高级句式」。** 用户明确说过「句式有点高级，不太符合我的写作习惯」「这样不符合我的水准了」。判断办法：本校四级水平的读者一遍能读懂即合格。[B113 B169 B196]
- **不用 `because` 解释特例取值。** 特例用 `If ...` 条件句，并说明「仅在此情形下这样取」。[B226 B227 B229]
- **`must` 一段内不连用两次。** [B248]
- **`Together with ...` 一段内不重复。** [B222]
- **`meaning that ...` 不连续两句都用。** [B223]
- **`whereas [17]` 这类对比句式，一段只用一次。** 用多了像模板。[B69]
- **一段内不连用两个 `and` 并列。** 改成 `while satisfying ...` 之类。[B75 B144 B147]
- **不堆括号。** 连用三个括号会显得像 AI 生成。[A98]
- **不要 `first` / `To remove them` 这类空过渡。** 直接说这一步做什么、带来什么结果。[A106 A116]
- **每个变换/代入之后要写「所以呢」。** 只给最终结果不给中间意义，读的人会懵。[A93 B105]

### 标点

- **不用冒号。** 需要说明时改成独立句子或 `that is` 从句。[B124]
- **不用分号。** 两个分句拆成两句，或用 `and` 连接。[B223]
- 检查清单里「标点」一栏指的就是这两条，不是泛指。[B261]

### 冠词

- 坐标轴、图题里的名词要带冠词：`the weighted-sum latency of user k`，不是 `Weighted-sum latency of user k`。[A64 A65]

## 10.2 段落逻辑与篇章

### 三句硬要求

1. **每段第一句要承接上一段。** 写完段首句，回头读上一段最后一句，两句意思重复就是错的，完全接不上也是错的。[B60 B61 B242]
2. **先原因，后结论。** 不要先说「这个问题非凸」，再用一串分析补理由；先说耦合在哪，再得出非凸。[A102]
3. **每个现象后面紧跟「为什么」。** 「现象 → 原因」成对出现，中间不插别的。[B166 B167]

### 摘要

- 摘要**独立于正文**：缩写要在摘要内重新定义全称。[B97]
- 摘要不写模型细节（并发执行、权重定义这类）。[B52]
- 摘要要提到 SDN/NFV 背景，用它引出 MEC 和反向散射。[B43]
- 摘要要比正文更简洁，不是正文的压缩版。[B30]

### 引言

- 三段分工固定：第一段业务背景与切片框架；第二段 MEC 类回顾；第三段 BackCom+MEC 回顾。[A49 A54 A140]
- 第二段开头要能承接第一段最后一句，并交代 MEC 基本原理；用 `Specifically` 开头会削弱分段感。[B83 B84]
- 结尾要有「目前已有研究……仍存在……」，不要只列文献。[B62]
- 「所有用户任务量相同」这类模型假设**不写进引言**，放系统模型，引言只正常回顾文献。[B231 B232]

### 图与图之间

- 两张对称的图，**先出现的那张说细，后一张只说「与图 X 的分析一致」**，不重复解释原因。[A67 A68 A69 B170]
- 每张图开头的句式固定：`Fig. X shows ...` → `It can be observed that ...` → 原因。[B166 B167]

## 10.3 文献回顾与引用

### 写法

- **不带人名。** 一律 `[n]`，与本领域参考文章一致。[A56]
- **主动被动混用**，全是被动句算不合格。可用的三种句式：作者在 `[n]` 中考虑了什么模型/做了什么；考虑了某模型某因素，作者在 `[n]` 中做了什么；某模型在某文献中被考虑。[B57 B58 B59]
- **文献之间要有关系。** 「在 `[4]` 的基础上，`[5]` 进一步……」这类衔接至少出现几次，不能一条条平铺。[A138 A139]
- **一条文献一句话**：说明模型是什么、大致做了什么工作，不要一条文献写三句。[A55 B238]
- 新加文献必须带编号，并说明插在引言第几段的哪个位置。[B20]

### 选取标准

- 以 IEEE 期刊论文为主，会议论文要先确认出处。[A47 A48 A49]
- 年份以 2020 年以后为主，近两年占比要大；太早的要换。[A49]
- 经典教材类旧引用（如凸优化教材）换成近年的 IEEE 综述或论文。[B173 B174]
- 期刊名用**缩写**，与参考文章一致。[B175]
- 引入新文献时，为了篇幅要同时说明替换掉哪一篇旧回顾。[B7]

### 真实性

- 每条文献核对：DOI、期刊全名、年份、卷期。查不到就标注「未核实」，**不编造**。[A48 B76]
- 用户会主动质疑「这是哪个期刊的、影响力怎么样」，所以列文献时要一并给出期刊和年份。[A48]

## 10.4 缩写、术语、符号

- **首次出现用全称并定义缩写，之后一律用缩写。** 前面出现过一次全称、后面再出现全称才定义缩写，是错的。[B86 B90]
- **只出现一次的名词不定义缩写**，因为后面用不到。[B203]
- 允许保留的常用缩写：SIC、CSI、QoS、IoT；其余按上两条处理。[B204]
- 单复数区分：单数 `EU`，多用户 `EUs`；缩写只在最初定义一次。[B28]
- 术语统一（一次定，全文跟）：
  - `energy station (ES)`、`edge user (EU)`、`power reflection coefficient (PRC)`、`weighted-sum latency`。[B28 A126 A63]
  - `D` = the required computation bits for each EU；`P0` = the transmit power at the ES。[B28 B29]
- **符号撞车要换字母。** `α_k` 与 `a_k` 混用会看错，改成 `γ`。[B163]
- `T` 与 `τ` 两个时间符号要能一眼区分，必要时直接用 `T`。[A107]
- **变量先定义再使用**，包括代换引入的新变量。[B249]
- **不作为优化变量的量不重复定义**。[A90]
- 改一个符号或术语就是**全局替换**：公式、正文、约束名、图题、仿真标题一起改，禁止留下两套定义。[A97 A126 A127]

## 10.5 图表与仿真分析文字

### 图题与坐标轴

- 横轴、纵轴标题要带冠词，并让轴标题与正文定义一致。[A63 A64]
- 图题格式：`纵轴 versus 横轴`，**不加** `under different ...` 这类后缀。[B31]
- 图题只写「A versus B」，不再在参数设置处重复定义变量。[B31]
- 轴标题末尾带上对应符号（如 `$K$`）。[B42 B131]
- 三张图放在同一行：`minipage` 宽 `0.31\linewidth`，图题与 label 对齐。[B270]
- 单张图宽用数值写法 `width=0.45\textwidth`，方便自己调。[B236]

### 仿真章节怎么写

- 开头一段：`In this section, we evaluate the performance of the proposed scheme through simulations and compare it with complete offloading and complete local computing.` 并说明对比方案是**所有用户**全部卸载或全部本地。[B116 B117 B256]
- 不再单独解释 benchmark 是什么（过度解释）。[B117]
- 每张图：`Fig. X shows ...` → 观察到什么 → 为什么。[B166]
- 趋势只说方向，**不点具体数值**（「D=20 的曲线高于 D=10」这类要改成「任务量越大时延越高」）。[A70]
- 图 2 和图 3 有对称内容时，后一张用「与图 2 的说明一致」，不再重述原因。[B170]

### 禁写清单（写进去会被要求删）

| 禁写 | 理由 | 证据 |
| --- | --- | --- |
| 「提升 5%」「降低了 X%」这类量化收益 | 参考文章只描述现象与原因 | A37 |
| 蒙特卡洛、信道实现次数、平均次数 | 业界默认做法，不必写 | A59 B38 |
| 固定信道数（如 1200） | 参考文章都不写 | A38 |
| 末尾「未来工作/可扩展到……」 | 参考文章不写 | B172 |
| `Performance Evaluation` 之类子小节 | 短文不分子节，占篇幅 | A39 |
| 仿真里再定义一遍模型符号 | 系统模型已定义 | B31 |

## 10.6 公式与优化问题

- 约束统一编号 `C1, C2, ...`，正文用编号指代，不写 `Constraint (8e)` 这类重复句式。[A89 A91]
- 约束顺序与上一版问题**一一对应**；没有变化的约束放到最后按序排列，不重复展开。[A111 B192]
- 变量代换后，约束要体现变换结果，并说明「由上述代换得到 P1」；不要在提出 P1 之前就把新约束全列一遍再重复。[A96 B194]
- 每个代换要说明「代入了什么、代入到哪、因此哪个约束变成什么」，不能只抛最终结果。[A93 B103 B104]
- 边界情况（零任务、零时长）**压缩成一句**，不展开正推反推。[B123 B153]
- 凸性证明直接对目标函数求二阶导，不额外定义临时函数再求导。[A128]
- 求和号用 `\sum\nolimits`，不用 `\sum\limits`。[B276]
- 公式环境上下间距、约束行间距可压缩，但只压 `P0` 那一个环境，别动全局格式。[B283]

## 10.7 篇幅

- 目标是**五页整，刚好塞满**。差 1/8 页可接受，差半页必须调。[A120]
- 页数超标时，优先级：删文献回顾（一次一篇，说明删哪篇及影响）→ 压公式环境间距 → 精简重复解释。**不要动图**。[B281 B282 B283]
- 页数不足时，不要靠堆砌废话补；补在模型推导、约束说明这类有信息量的地方。[A99]
- 每次改动后报「页数变化多少行」，不要只说「已精简」。[A89 B278]
