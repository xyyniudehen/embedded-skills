# 仿真规则（academic-sim-run）

规则来源：SR 论文四个会话的用户原话，证据编号见 `../../academic-voice/references/evidence.md`。
目标不是写「可扩展的软件工程」，是写**看得懂、能复现、能出图**的论文仿真代码。

---

## 20.1 代码形态

- **线性执行逻辑为主。** 主脚本从上往下读就能看懂：参数 → 循环 → 求解 → 保存 → 画图。[B207]
- **辅助函数只封装重复的数学计算**，不为了「可扩展」造基类、接口、抽象层。[B207]
- **变量名用数学符号**：`alpha`、`beta`、`gamma`、`omega`、`t_b`、`tau`。**禁止** `manager`、`handler`、`factory`、`utils`、`service` 这类工程词。[B207]
- **不引入调用链。** 每多一层 `root = fileparts(mfilename('fullpath')); addpath(...)`，就要能说清为什么需要；说不清就删。[B211]
- **每个脚本最上面一段注释写清**：这个文件做什么、输入是什么、输出到哪。[B210]
- **模块级写中文注释**，说明这一段在算哪个公式、对应论文哪一节。[B210]
- 路径检索相关代码**必须注释原因**，否则读者不知道这段是干什么的。[B215]

## 20.2 运行

### 并行池

- 必须开并行池。worker 数 = `min(8, 物理核数, 集群允许容量)`，**运行时探测**，不写死。[A19]
- 探测方法：`feature('numcores')` 或 `parcluster('local').NumWorkers`，把最终取到的数字打印出来。
- 本机曾出现「代码上限 8、实际只给 6」，所以取到 6 是正常结果，不是错误。
- 每张图之间关闭并重建并行池，避免残留状态污染下一张图。[A31]

### 无人值守

- 长跑前把方案定死，之后**不再要求用户确认**。用户原话是「我要睡觉了，不用再给我审核」「不要再让我点同意什么的了」。[A30 A32]
- 跑完自己保存、打印结果目录、结束，不空等。**等待只会浪费额度。** [A20]
- 运行前加自检：参数维度、权重归一化、距离、信道文件签名、曲线条数。异常立即停止，**不覆盖已有有效结果**。[A31]
- 每 100 个信道保存一次检查点，崩溃最多损失当前未保存块。[A31]
- 异常退出时留证据：退出码、worker 数、内存、当前进度、最后检查点，写到 `validation/FORMAL_FAILURE_REPORT_*.txt`，**不自动重试**。[A31]

### 规模

- 正式跑之前不要启动全量规模（1000/2000 信道级）的探索性运行，先用小规模验证流程。[A1]
- 论文用的正式规模一旦确定（如 1200 信道），所有图统一，不混用。[A18]

## 20.3 换电脑、打包、路径探测

- 打包后的代码必须**在另一台机器的 MATLAB 上直接能跑**。[B212]
- 目标机器可能自带 CVX，也可能没有。按「正常下载流程会落到的目录」判断，不猜别的路径。[B213 B214]
- **禁止写死盘符**（如把 MATLAB 安装位置固定成某个盘符路径）。探测顺序固定：

```text
1. $env:MATLAB_ROOT（若设置）
2. where.exe matlab  → 取第一条
3. 常见安装根目录下扫描 matlab.exe（只扫已知厂商目录，不通扫全盘）
4. 都没有 → 停下问用户，并把已尝试的路径打印出来
```

- 探测结果必须打印，例如 `MATLAB R2022a @ <path>`，让用户能核对。[B39]
- CVX 同理：先探测 `cvx_setup` 是否在路径上，再决定是否 `addpath`；每一步打印做了什么。

## 20.4 出图

- **改图题、坐标轴、字体、图例，先看有没有 `.fig`。** 有 `.fig` 就在 `.fig` 上改，**不重跑仿真**。[B38]
- 每次出图同时保存 `.fig` 和 `.pdf`（矢量），两版都要。[A37]
- 论文用图的宽度按正文要求给（如 `width=0.45\textwidth`），三图同行用 `0.31\linewidth`。[B236 B270]
- 图内文字、图例、刻度字体三张图保持一致，只有曲线内容不同。[A59]
- 图题、轴标题的写法归 `academic-voice` 的 10.5，本文件只管生成。

## 20.5 改代码后怎么证明等价

- 重写求解代码后，**必须用旧代码和新代码在同一组设置下对比**（约 20 个信道即可），结果一致才继续。[B209]
- 对比要固定：同一信道文件、同一随机种子、同一信道编号。三者任一不同，结果差异不能说明问题。
- 差异超阈值时先查参数与约束，不先怀疑 CVX。

## 20.6 结果与论文的对应

- 一套「图-代码-结果」三元组：每张图要能说清 用哪个脚本、哪个结果目录、哪个 `.fig`。[C3]
- 主稿里的图就是正式结果；新结果出来前不要用旧图冒充新结果，要标注「待替换」。
- 结果目录命名带版本与规模（如 `results_..._v3_power_N1200`），不覆盖历史目录。[A31]
- 论文里**不写**信道实现次数、平均次数、蒙特卡洛细节（见 `academic-voice` 10.5 禁写清单）。[A38 A59]

## 20.7 不做什么

| 不做 | 原因 | 证据 |
| --- | --- | --- |
| 造基类、接口、抽象层 | 论文仿真只需要跑一次出图 | B207 |
| 把路径写成绝对盘符 | 换机器就崩 | B212 |
| 长跑中途要求用户确认 | 用户睡觉时点不了，进度会卡住 | A30 A32 |
| 自动重试崩溃的任务 | 会反复崩，且掩盖真实原因 | A31 |
| 改图时重跑仿真 | `.fig` 直接改即可，重跑几小时 | B38 |
| 目录里堆与编译无关的文件 | 论文目录只留 tex、pdf、bib 与图 | B279 |
