# 论文评阅

评别人的论文，或投稿前自查。本技能只管**产出是问题清单**的工作，不写正文、不改代码。

## 什么时候加载

- 用户给了 PDF（或 `.tex`）让你「看看有什么问题」
- 投稿前自查
- 判断某个问题是否「必须改」

改正文 → `academic-voice`；跑仿真 → `academic-sim-run`。

## 三条边界

1. **只依据能看到的材料。** 只有 PDF 时，不得假定能看到源码、代码、原始数据。
2. **只评不改。** 除非明确要求，不重写、不替换原文、不改文件。
3. **不套用本项目内容。** 评别人的论文时，禁止把当前自己论文的模型、变量、参数、文献、结论套过去。

## 流程

```text
1. 给审核方案（检查范围 / 判断优先级 / PDF 无法确认的部分 / 哪些常见问题不会无依据列为主要问题）
2. 等确认
3. 按固定结构出完整报告
```

用户说「检查吧」「直接看」时，第 1 步压缩成 3~5 行方案即可，不要跳过。

## 规则正文

读 `references/review-standard.md`：

| 要做什么 | 章节 |
| --- | --- |
| 输入边界与可验证性三档 | 30.1 |
| 阅读顺序与判断优先级 | 30.2 |
| 技术检查清单（问题、模型、公式、算法、实验） | 30.3 |
| 语言检查（不重复写作规则，只指向） | 30.4 |
| 分级与记录格式 | 30.5 |
| 报告结构与禁止事项 | 30.6 |

## 输出格式

严格按 30.5 的记录格式，一个问题一条。最后补一段「修改优先级」，按「必须先改 / 建议改 / 可选」分三档，每档最多 5 条。

报告里**不写**笼统评语（「逻辑需要加强」「表达不够清楚」），写不出位置的问题不列。
