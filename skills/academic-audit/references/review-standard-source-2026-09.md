# PDF 论文评阅标准

本文件用于指导 Codex 仅根据一篇论文的 PDF 进行评阅。它总结了 SR 论文历史对话中形成的评阅习惯，但不包含 SR 项目的专属模型、变量、参数、文献或结论。评阅其他论文时，不得把 SR 项目的技术内容套用到目标论文中。

## 1. 任务目标

按照一篇 EI 会议论文的基本标准，对目标论文进行独立、具体、可执行的评阅。重点判断：

- 论文的研究问题是否明确
- 技术路线和数学模型是否自洽
- 论证、实验和结论是否相互支持
- 文章结构和段落衔接是否清楚
- 英语表达是否自然、简洁、符合学术论文习惯
- 图表、公式、符号、缩写、引用和 PDF 排版是否规范

评阅输出不是改稿。除非用户之后明确要求，否则不得直接修改论文、重写整篇文章或替换原文。

## 2. 输入边界

默认输入只有：

1. 本标准文件
2. 目标论文 PDF

不得假定能够看到目标论文的 LaTeX 源码、Word 源文件、MATLAB/Python 代码、原始数据、求解器日志或作者未放入 PDF 的补充材料。

因此，评阅时必须区分：

- **PDF 可以直接确认的问题**：可以明确指出并定位
- **从 PDF 可以合理怀疑的问题**：应说明依据和不确定性
- **PDF 无法验证的内容**：放入“需要作者核实”，不能直接判定为错误

## 3. 评阅流程

### 3.1 先给审核方案

如果用户没有明确要求立即开始详细评阅，先输出审核方案，不要直接开始逐句批改。方案应说明：

- 将检查哪些部分
- 哪些内容只做有限判断
- 哪些内容不作为重点
- 最终报告的组织方式

等待用户确认后，再进行完整评阅。

### 3.2 阅读顺序

建议按以下顺序阅读 PDF：

1. 标题、摘要和关键词
2. 引言和相关工作
3. 系统模型、问题定义和方法
4. 理论分析、算法或复杂度
5. 仿真/实验设置和结果
6. 结论
7. 全文公式、图表、引用和排版回查

不能只根据摘要或某一个段落判断整篇论文。

### 3.3 判断优先级

问题按以下优先级处理：

1. 数学错误、模型矛盾或结论不成立
2. 技术逻辑断裂、关键假设缺失或实验不能支撑结论
3. 变量、公式、图表、引用或术语前后不一致
4. 语法错误、缩写错误和明显表达问题
5. 标点、句式重复、段落衔接和排版优化

不要把低优先级语言偏好写成主要技术缺陷。

## 4. 技术内容检查标准

### 4.1 研究问题和贡献

检查：

- 论文研究的问题、场景和目标是否明确
- 研究动机是否由前文自然引出
- 所谓“研究缺口”是否确实由相关工作支持
- 贡献是否具体，是否与正文方法和结果一一对应
- 是否把普通的参数设置、已有方法或常规推导夸大为主要贡献
- 摘要、引言、结论中的贡献表述是否一致

如果贡献表述过强，应说明是“证据不足”还是“表述过度”，不能笼统地说创新性不足。

### 4.2 文献回顾

检查：

- 文献是否围绕研究问题组织，而不是逐篇罗列
- 相邻文献之间的关系、差异和发展脉络是否清楚
- 每条引用是否真的支持对应陈述
- 是否存在关键方向、经典方法或近年工作的明显遗漏
- 是否把文献没有做的事情归因给文献
- 是否过度使用作者姓名、被动句或相同的回顾句式
- 文献回顾最后是否自然导向本文工作

不能仅因为引用数量少就判定文献回顾有问题。应结合研究主题、年份、会议/期刊层次和论述完整性判断。

### 4.3 系统模型和假设

检查：

- 系统组成、用户/节点、链路和资源是否定义清楚
- 变量和参数是否在首次使用时说明
- 假设是否明确、合理，并在后续公式中真正使用
- 物理过程的时间顺序、能量流、信息流和资源分配是否一致
- 模型中的基本假设是否导致明显的未定义表达式或矛盾约束
- 是否把系统描述、优化变量和仿真设定混在一起

如果某一假设在该领域属于常见建模约定，不要仅因为它被简略说明就直接认定为错误。应指出是否影响可复现性或结论有效性。

### 4.4 数学公式和优化问题

检查：

- 变量集合是否包含目标函数和约束中出现的变量
- 每个符号是否有定义，且同一符号是否始终表示同一含义
- 约束编号、公式编号和正文引用是否对应
- 约束的物理含义是否正确，例如任务、能量、时间、功率和容量约束
- 变量的定义域和主要约束是否清楚
- 变换前后的问题是否逐项对应
- 如果声称等价、凸、全局最优或可恢复，正文是否提供了足够的理由
- 目标函数和约束的凸性/非凸性判断是否正确
- 算法输出是否真的能恢复原问题变量

只要 PDF 中的数学定义足以支持判断，就给出具体公式和位置。若需要代码或数值验证才能确认，不得直接下结论。

### 4.5 算法和理论分析

检查：

- 算法输入、输出和迭代过程是否明确
- 算法是否与前面建立的问题相对应
- 复杂度分析的对象、规模和主要步骤是否说明
- 收敛性、最优性、下界或等价性结论是否与证明匹配
- 是否把局部最优、驻点或可行解错误地称为全局最优
- 是否遗漏导致算法无法执行的必要输入条件

### 4.6 仿真和实验

仅根据 PDF 检查：

- 参数是否足以理解实验设置
- 对比方法是否合理且定义清楚
- 图表是否能支撑正文结论
- 是否解释主要趋势和异常现象
- 是否说明评价指标、实验范围和基线设置
- 是否存在只展示有利结果、缺少必要对比或结论超出实验范围的问题
- 多次随机实验、Monte Carlo 或不可行样本的处理是否至少被说明到足以理解结果

不默认因为 PDF 没有给出完整代码、随机种子或全部中间结果就判定论文不可接受。此类问题应列为可复现性风险或需要作者核实，除非它已经使结果无法解释。

## 5. 语言和结构标准

### 5.1 总体表达

要求：

- 句子简洁、自然、准确
- 技术含义优先于复杂句式
- 不为了显得正式而使用作者明显不习惯的高级表达
- 不无依据地增加系统细节、背景或解释
- 同一段中避免连续使用相同连接词和相同句式
- 避免不必要的冒号和分号
- 避免连续堆叠多个 `and`
- 主动句和被动句可以混用，但不能出现被动句过度集中、句式机械重复

### 5.2 段落逻辑

重点检查：

- 每段第一句是否承接上一段
- 新概念是否有自然引入
- 因果关系、转折关系和递进关系是否真正成立
- 解释是否紧跟对应的现象、公式或结论
- 是否出现“先给结论，后文才补充前提”的突兀结构
- 是否重复上一段已经表达过的内容
- 引言是否从背景自然过渡到问题、文献缺口和本文工作
- 仿真分析是否先描述现象，再解释原因，最后说明比较结果

不要只指出“衔接不好”。必须说明缺少的是背景、因果、转折、限定条件还是结论承接。

### 5.3 摘要

检查摘要是否按合理顺序包含：

1. 研究背景或应用场景
2. 研究问题
3. 方法或主要技术路线
4. 关键结果或理论结论
5. 主要贡献

摘要不应塞入过多系统模型细节、变量定义、约束编号或不影响读者理解的实现细节。缩写在摘要中应独立处理，不能默认依赖正文定义。

### 5.4 缩写和术语

- 第一次出现时给出全称并定义缩写
- 后文统一使用缩写
- 只出现一次且后文不会再次使用的术语，不强行定义缩写
- 摘要视为相对独立的文本，摘要中的缩写需要单独判断
- 单数、复数和带编号的术语要保持一致
- 同一概念不能在不同位置随意更换名称

### 5.5 图表和图题

检查：

- 图题是否说明了纵轴、横轴和必要条件
- 横坐标和纵坐标的文字是否与正文一致
- 图中符号、单位、图例和正文是否一致
- 正文是否真正解释了图中的主要趋势
- 图题是否过度解释已经在正文说明的内容
- 图表是否存在裁切、字体过小、编号错误、空白过大或内容重叠

如果只能看到 PDF，不能判断图是由什么代码生成的，也不能要求作者重新运行代码来证明图形来源。

## 6. 默认不作为主要问题反复提出的内容

以下内容除非直接造成数学错误、物理矛盾或无法解释的结果，否则不应反复列为主要问题：

- 领域内常见且已在文中明确的同步时隙建模
- 正常的 Monte Carlo 仿真流程
- 常规不可行信道筛选或处理
- 参考文献中同样采用的远程执行时间忽略假设
- 不影响结论的噪声分布细节
- 单纯属于个人偏好的图题表达
- 仅为了增加篇幅而补充背景或展望
- 只涉及字面偏好、但不影响理解的同义词选择

如果认为其中某项确实需要修改，必须说明它具体影响了什么，而不能只说“最好更完整”。

## 7. 问题分级

### 主要问题

会影响技术正确性、论文可信度、主要结论、方法可执行性或审稿决定的问题。例如：

- 公式或约束明显错误
- 模型和实验设置不一致
- 关键假设缺失导致结论无法成立
- 文献错误支撑核心研究缺口
- 图表不能支持主要结论

### 次要问题

不改变核心结论，但会影响清晰度、严谨性、可复现性或论文完整性的问题。例如：

- 符号首次定义不清
- 变量前后名称不一致
- 某段逻辑跳跃
- 重要参数说明不足
- 图题或图例不完整

### 语言和排版问题

包括：

- 语法错误
- 句式重复
- 不自然的连接词
- 缩写和标点问题
- 图表编号、分页、字体或 PDF 排版问题

### 可选优化

只提升表达或可读性，不修改也不会影响论文正确性的问题。不能把可选优化包装成必须修改项。

## 8. 每个问题的固定记录格式

每个问题都应尽可能包含：

```text
位置：页码、章节、公式、图表或段落
原文：只引用判断所需的短句或公式
问题类型：技术 / 逻辑 / 文献 / 语法 / 缩写 / 排版 / 可选优化
严重程度：主要问题 / 次要问题 / 语言和排版 / 可选优化
具体问题：准确说明哪里不对
原因：说明为什么构成问题
影响：说明对理解、正确性、复现或审稿判断的影响
建议：给出具体处理方向；必要时给出简短示例
PDF 可验证性：已确认 / 有风险但需核实 / PDF 无法确认
```

不能只写“表达不够清楚”“逻辑需要加强”“建议补充讨论”等没有位置和原因的泛化意见。

## 9. 固定评阅输出结构

完整评阅报告按以下顺序输出：

1. **审核范围和依据**
2. **总体评价**
3. **主要问题**
4. **次要问题**
5. **公式、符号和模型一致性**
6. **文献和研究逻辑**
7. **实验、图表和结论**
8. **语言、缩写、标点和排版**
9. **需要作者核实的内容**
10. **可选优化建议**
11. **修改优先级**

如果没有发现某一类问题，应明确写“未发现明确问题”，不要为了凑数量而制造问题。

总体评价应放在问题之后或紧接审核范围之后，但不能用长篇泛泛表扬代替具体问题。

## 10. 评阅时的禁止事项

- 不直接修改目标 PDF 或其他文件
- 不把 SR 项目的具体技术内容套入其他论文
- 不根据作者没有提供的代码或数据进行猜测
- 不把个人语言偏好说成客观语法错误
- 不为了列出更多问题而重复同一个问题
- 不把一个可以通过一句话澄清的小问题夸大为方法缺陷
- 不在没有证据时断言某个公式、仿真结果或引用一定错误
- 不只给总体分数而不提供定位和依据

## 11. 推荐提示词

将本文件和目标论文 PDF 一起提供给新会话后，可以使用以下提示词：

```text
请先完整读取 PAPER_REVIEW_STANDARD_FROM_SR_HISTORY.md，再阅读我提供的目标论文 PDF。

这次任务是评阅另一篇论文，不是修改 SR 项目，也不能把 SR 项目的具体模型、变量、参数、文献或结论套用到目标论文中。你只能依据 PDF 中可见的正文、公式、图表和排版进行判断。

请先给出详细的审核方案，不要立即开始逐句修改或直接改文件。审核方案需要说明检查范围、判断优先级、PDF 无法确认的内容，以及哪些常见问题不会被无依据地列为主要问题。等我确认后，再给出完整评阅报告。

完整评阅时，请重点检查：研究问题和贡献、引言逻辑、文献回顾关系、系统模型和假设、公式和优化问题、变量与约束一致性、算法和理论分析、仿真/实验设置、图表与结论、语法、段落衔接、缩写、标点、重复句式和 PDF 排版。

请按“主要问题、次要问题、公式/符号/模型一致性、文献和研究逻辑、实验和图表、语言和排版、需要作者核实、可选优化、修改优先级”的顺序输出。每个问题都必须给出位置、原文短引、问题类型、具体原因、影响、建议处理方式和 PDF 可验证性。

请区分必须修改的问题和可选润色，不要为了显得全面而制造问题。如果 PDF 无法验证某项内容，请明确标记为“需要作者核实”，不要自行猜测。除非我之后明确要求，否则只评阅，不重写或修改论文。
```

## 12. 最简提示词

如果标准文件已经被新会话读取，也可以使用：

```text
按 PAPER_REVIEW_STANDARD_FROM_SR_HISTORY.md 的标准评阅这篇 PDF。先给审核方案，等我确认后再进行详细评阅。只依据 PDF，不修改文件，不把 SR 项目的具体内容套用到这篇论文。所有问题都要定位、分级并说明影响；无法由 PDF 确认的内容列入“需要作者核实”。
```
