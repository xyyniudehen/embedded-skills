## 30.1 输入边界与可验证性

默认输入只有两样：本标准和目标论文 PDF。

不得假定能看到 LaTeX 源码、Word 源文件、MATLAB/Python 代码、原始数据、求解器日志或补充材料。

### 外部核对

允许查证 DOI、期刊、卷期、月份这类外部信息，但：

- **结论档位按 PDF 内证据算。** 外部核对不能把「有风险需核实」升成「已确认」。
- 外部核对写进「依据」并注明来源，例如「（外部核对 IEEE Xplore，非 PDF 内证据）」。
- 外部信息与 PDF 冲突时，指出冲突，不要单方面判定 PDF 错。

因此每个问题必须标注**可验证性三档**：

| 档位 | 含义 | 能不能判为错误 |
| --- | --- | --- |
| 已确认 | PDF 里能直接看到 | 可以明确判定并定位 |
| 有风险需核实 | 从 PDF 可合理怀疑，但缺一半证据 | 只能写成风险，说明依据 |
| PDF 无法确认 | 需要源码、数据或运行才能判断 | 进「需要作者核实」，**不得判定** |

## 30.2 流程与优先级

阅读顺序：标题/摘要/关键词 → 引言与相关工作 → 系统模型与问题定义 → 理论分析或算法 → 仿真设置与结果 → 结论 → 全文公式、图表、引用、排版回查。**不能只根据摘要或某一段判断全篇。**

### 先粗读，再出方案，等确认

1. **粗读**：按上面的顺序快速过一遍，只形成"风险大概在哪"的判断，不逐条记问题。
2. **方案 + 待确认**：给 3~5 行审核方案，并列**最多 5 条**拿不准、且会改变结论的假设或背景问题。只问这类：目标（投稿自查 / 审别人的稿）、页数或期刊限制、参数缺失是篇幅所限还是疏漏、baseline 是否同训练预算、是否允许外部核对。
3. **等确认**：用户回话后再出完整报告。
4. **完整报告**：按 30.6 的结构输出。

只有用户明确说「直接出报告」才跳过第 3 步；「检查吧」「看看有什么问题」都不算例外。

判断优先级（从高到低）：

1. 数学错误、模型矛盾、结论不成立
2. 技术逻辑断裂、关键假设缺失、实验不能支撑结论
3. 变量/公式/图表/引用/术语前后不一致
4. 语法错误、缩写错误、明显表达问题
5. 标点、句式重复、段落衔接、排版优化

**低优先级的语言偏好不得写成主要技术缺陷。**

## 30.3 技术检查清单

### 研究问题与贡献

- 问题、场景、目标是否明确；动机是否由前文自然引出
- 「研究缺口」是否确由相关工作支持
- 贡献是否具体、与方法和结果一一对应
- 是否把常规参数设置或已有方法夸大为贡献
- 摘要、引言、结论的贡献表述是否一致

贡献过强时，要区分「证据不足」还是「表述过度」，不能一句「创新性不足」。

### 文献回顾

- 是否围绕问题组织，而不是逐篇罗列
- 相邻文献的关系、差异、脉络是否清楚
- 每条引用是否真的支持对应陈述；有没有把文献没做的事归因给它
- 关键方向的近年工作是否明显遗漏
- 是否过度使用人名、被动句或同一句式（判据见 `writing-rules.md` 10.3）

不能仅因引用数量少就判定文献回顾有问题。

### 系统模型与假设

- 组成、节点、链路、资源是否定义清楚；变量是否首次使用时说明
- 假设是否明确、合理，且在后续公式中真正被使用
- 时间顺序、能量流、信息流、资源分配是否自洽
- 是否把系统描述、优化变量、仿真设定混在一起

领域内常见建模约定不因简略说明就判错，只需指出是否影响可复现性。

### 数学公式与优化问题

- 变量集合是否包含目标函数和约束中出现的所有变量
- 每个符号是否有定义，同一符号是否始终同义
- 约束/公式编号与正文引用是否对应
- 约束物理含义是否正确（任务、能量、时间、功率、容量）
- 变换前后是否逐项对应；声称等价/凸/全局最优时理由是否充分
- 凸性判断是否正确；算法解是否真能恢复原变量

PDF 中的数学定义足以判断时，给出具体公式和位置。

### 算法与理论

- 输入、输出、迭代是否明确；是否与前文问题对应
- 复杂度分析对象与主要步骤是否说明
- 收敛性、最优性、下界、等价性结论是否与证明匹配
- 是否把局部最优或可行解称为全局最优
- 是否遗漏执行所需的输入条件

### 仿真与实验

- 参数是否足以理解设置；对比方法是否合理且定义清楚
- 图表能否支撑正文结论；主要趋势与异常是否解释
- 是否只展示有利结果、结论是否超出实验范围
- 随机实验或不可行样本的处理是否说明到「能理解结果」的程度

PDF 没给代码或随机种子，**不构成拒稿理由**，列为可复现性风险或待核实。

## 30.4 语言检查

判据全部见 `writing-rules.md`，本节只说「在评阅里怎么用」：

- 语言问题最高只到「语言和排版问题」这一档，**不上调为主要问题**，除非已经导致技术含义歧义。
- 引用 10.1 的禁词表、10.4 的缩写规则时，只列**影响理解**的项；纯偏好项进「可选优化」。
- 主动/被动混用、句式重复、连接词机械重复，属于可指出项，但要给出具体位置和原文短引。

## 30.5 分级与记录格式

### 分级

| 级别 | 判据 |
| --- | --- |
| 主要问题 | 影响技术正确性、可信度、主要结论或方法可执行性 |
| 次要问题 | 不改变结论，但影响清晰度、严谨性或可复现性 |
| 语言和排版 | 语法、句式、缩写、标点、编号、分页、字体 |
| 可选优化 | 只提升表达，不改也不影响正确性 |

**不得把可选优化包装成必须修改项。**

### 每条问题的固定字段

```text
位置：页码 / 章节 / 公式号 / 图号 / 段落
原文：只引用判断所需的短句或公式
类型：技术 / 逻辑 / 文献 / 语法 / 缩写 / 排版 / 可选优化
级别：主要 / 次要 / 语言和排版 / 可选优化
问题：具体哪里不对
原因：为什么构成问题
影响：影响理解、正确性、复现还是审稿判断
建议：具体处理方向，必要时给一句示例
可验证性：已确认 / 有风险需核实 / PDF 无法确认
```

写不出「位置」的问题不要列。次要问题编号按出现顺序连续（S1、S2…），不跨节跳号。

## 30.6 报告结构与禁止事项

报告顺序固定：

1. 审核范围和依据
2. 主要问题
3. 次要问题
4. 公式、符号和模型一致性
5. 文献和研究逻辑
6. 实验、图表和结论
7. 语言、缩写、标点和排版
8. 需要作者核实
9. 可选优化建议
10. 总体评价（放在问题之后，不用长篇表扬代替问题）
11. 修改优先级（必须先改 / 建议改 / 可选）

没有某类问题时，明确写「未发现明确问题」，不为凑数量制造问题。

### 默认不作为主要问题反复提出的内容

除非直接造成数学错误、物理矛盾或结果无法解释：

- 领域内常见且已明确的同步时隙建模
- 正常的 Monte Carlo 流程
- 常规不可行样本筛选
- 文献同样采用的远程执行时间忽略假设
- 不影响结论的噪声分布细节
- 纯个人偏好的图题表达
- 为增加篇幅而补的背景或展望
- 不影响理解的字面同义词选择

认为某项确实要改时，必须说明它具体影响了什么。

### 禁止

- 不修改目标 PDF 或其他文件
- 不把本项目论文的技术内容套进目标论文
- 不根据未提供的代码或数据猜测
- 不把个人语言偏好说成客观语法错误
- 不重复同一个问题凑数量
- 不把小问题夸大为方法缺陷
- 不在没有证据时断言公式、结果或引用一定错误
- 不只给总评而不给定位和依据
