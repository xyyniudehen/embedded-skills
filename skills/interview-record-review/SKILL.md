# 面试录音复盘

## 目标

将录音、转写稿和用户补充材料整理成可复习的面试档案。必须保留原始信息，不能只输出“高频问题总结”而丢失完整问答或反问环节。

## 输入确认

1. 优先确认录音或逐字稿、公司名称、岗位名称。
2. 岗位要求/JD是可选输入。若缺失，只询问一次是否需要结合岗位分析；用户不提供时直接继续，并在文档中标明未进行JD匹配评价。
3. 如有候选人简历、项目背景或既有面试备书，作为背景资料单独标记，不与录音事实混写。
4. 本地录音有可用转写工具时先转写；没有工具或转写失败时，要求用户提供逐字稿或可读片段，不假装已经听过录音。

## 事实边界

- 原始转写、用户补充、背景资料、复盘分析、待确认内容分开标记。
- 听不清处保留时间戳并写 `[听不清]`；术语不确定时写 `[术语待确认]`，禁止按经验补全为确定事实。
- 不替候选人虚构项目数据、个人贡献、面试官评价或未说过的回答。改进答案必须明确标为“建议表达”，不能伪装成原回答。
- 对技术回答按“正确、部分正确、缺失、与现有材料冲突、无法判断”评价，并给出依据。

## 输出顺序

默认生成 Markdown；用户要求 Word 时再生成 DOCX。文件名使用 `公司_岗位_面试复盘_日期`，避免覆盖原始转写。

### 原始记录完整性（硬约束）

原始记录与复盘分析必须分开：逐题原话在前，复盘评价在后，完整连续原文收在文末附录。任何情况下都不能用摘要替代原文。

1. 面试官原话、候选人原话、追问、反馈和反问必须来自录音或原始转写，不得先把回答概括成“要点”再当作原文。
2. 原始记录以 ASR 逐字内容为准；只允许做说话人标记、按上下文分段、去除明显无意义的重复口头噪声，并保留 `[听不清]`、`[术语待确认]` 等不确定标记。
3. 必须保留完整连续 ASR 原文：放在文末“附录：完整连续 ASR 原文”，或作为同目录附件并在文末给出明确链接和原文位置说明；不能只给一个链接而不说明原文在哪。
4. 不得以“内容过长”“已经附原始 JSON/音频”为由省略原始记录。如果交付格式无法嵌入全文，至少在 Markdown 中保留完整的“原始完整转写”章节。
5. 无法可靠切分说话人时标注“按上下文切分”或“说话人待确认”，不能假装有说话人分轨；录音没有说话人分离或时间戳时，在记录信息中说明限制。

### 逐题原话与复盘对照

复盘主体必须按面试出现顺序逐题整理。每题都要把该题对应的原始问答和分析放在一起，不能把完整转写堆在开头，再让读者自行寻找对应内容。

每道题使用以下结构：

```markdown
### <题号>. <题目名称>

**面试官原话（按上下文切分）：**
> <该题对应的原始问题及追问>

**候选人原话（自动转写）：**
> <候选人针对该题的原始回答；多轮追问分别保留>

#### 复盘评价与改进

**回答总结：** [复盘分析] <概括候选人实际回答的内容>

**评价：** [复盘分析] <正确 / 部分正确 / 缺失 / 与现有材料冲突 / 无法判断，并说明依据>

**事实依据与待确认：** <区分录音事实、用户补充、背景资料、推断和待确认项>

**建议表达：** [建议表达] <基于已知事实优化后的回答，不得冒充原话>

**可能追问：** <下一轮可能追问及需要准备的依据>
```

执行要求：

- 面试官原话、候选人原话、追问和反馈必须来自录音或转写。原话保留口语、重复和 ASR 识别错误；可以按上下文切分说话人，但不能把总结润色成原话。
- 每题先呈现对应原话，再写回答总结、评价、事实核对和建议表达。
- 无法可靠切分说话人时标注“按上下文切分”或“说话人待确认”，不能假装有说话人分轨。
- 术语疑似 ASR 错误时，原话仍保留；只在事实依据或建议表达中注明可能的正确术语及其待确认状态。
- 面试官复述、质疑、纠正和评价单独作为追问与反馈原话保留。
- 每题的建议表达必须基于候选人真实经历。录音没有的数据、职责、项目成果和已验证状态不得补写。

完整连续 ASR 原文作为追溯材料放在文末附录，不替代逐题原话。

完整输出顺序固定为：

1. 记录信息：日期、公司、岗位、轮次、录音/转写来源、是否有 JD 和转写限制。
2. 面试问题大纲：按出现顺序编号。
3. 逐题原话与复盘对照：每题按“问题原话 → 回答原话 → 追问/反馈原话 → 总结 → 评价 → 事实依据/待确认 → 建议表达 → 可能追问”排列。
4. 反问环节原话与复盘：候选人原反问、面试官原回答、问题价值、风险和更合适问法。
5. 总体结论：技术覆盖、项目可信度、表达结构、事实风险；有 JD 才评价岗位匹配。
6. 复习行动清单：立即补充、短期练习、材料待确认。
7. 附录：完整连续 ASR 原文；若原文另存附件，文末清晰链接并说明位置。

详细字段和标记规范见 [references/review-template.md](references/review-template.md)。
